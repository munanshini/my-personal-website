# 个人网站独立页面导航与深色模式设计

## 1. 目标与范围

本轮改版解决两个问题：

1. 将当前连续瀑布流调整为“一级菜单切换独立页面”，让招聘者能够快速定位工作、内容、近况和联系方式。
2. 建立完整的浅色 / 深色主题系统，在不改变个人品牌定位的前提下提升视觉一致性和夜间阅读体验。

网站继续以“AI 产品经理”为第一身份，交互设计与产品审美作为能力证明，不改变既有内容事实，不增加未经验证的项目数据。

本轮不扩展 AI 助手能力、不新增后台系统，也不制作尚无完整材料的项目详情内容。

## 2. 核心体验原则

- 一级菜单对应独立页面，不再通过长页面滚动定位内容。
- 页面内部内容超过一屏时正常纵向滚动，不使用强制全屏轮播。
- 首页保持接近一个视口的品牌封面，其余页面采用“页面首屏 + 内容主体”的阅读结构。
- 使用大标题、索引标签、细分隔线和留白建立层级，减少重复圆角卡片和厚重阴影。
- 保留现有红色信号色，不复制参考站的荧光绿色。
- 不恢复任何网格背景或网格装饰。
- 动效只服务于页面切换、当前状态和可点击提示，不制造持续干扰。

## 3. 导航与路由

### 3.1 一级页面

| 菜单 | 地址 | 页面职责 |
| --- | --- | --- |
| INDEX 首页 | `#index` | 人物主视觉、AI 产品经理定位、精简自我介绍 |
| WORK 工作 | `#work` | 公司与项目合并展示，突出职责、判断和结果证据 |
| WORDS 内容 | `#words` | 区分文章、视频和 Vibe Coding 内容 |
| NOW 现在 | `#now` | 按日期展示近期思考、制作、阅读和生活动态 |
| CONTACT 联系 | `#contact` | 自我介绍、联系方式、微信二维码、平台入口和简历下载 |

继续使用哈希地址，而不是新增服务端路由。原因是网站部署在 GitHub Pages，自定义域名刷新任意地址时，哈希路由不会触发服务器 404，也无需引入新的路由依赖。

### 3.2 页面切换行为

- 点击一级菜单后，只渲染目标页面，不滚动经过中间板块。
- 当前菜单状态由地址唯一决定，不再依赖 `scroll` 或 `IntersectionObserver` 判断。
- 浏览器前进 / 后退能够恢复对应页面。
- 页面切换时先淡出旧内容，再以轻微纵向位移淡入新内容；总时长控制在 300–450ms。
- `prefers-reduced-motion` 开启时取消位移和模糊，仅保留即时内容切换。
- 首页人物特效、AI 助手和 OPEN TO WORK 入口继续保留，但不参与页面路由状态。

### 3.3 二级项目页边界

WORK 页面会预留项目详情入口的数据结构和视觉位置。本轮只为已有完整内容的项目开放详情入口；材料不完整的项目不显示无效链接或“空页面”。后续地址采用 `#work/<slug>`，与 GitHub Pages 部署方式兼容。

## 4. 页面排版设计

### 4.1 全局框架

- 顶部导航从 Hero 内部移到应用全局层，所有页面保持同一位置和尺寸。
- 桌面内容最大宽度控制在约 1560–1640px，正文阅读区控制在约 720–900px。
- 页面左右留白使用响应式间距，不因超宽屏无限拉伸。
- 所有一级页面使用统一页头：页面编号 / 英文标签、主标题、简短说明。
- 分隔以低对比度单线为主，不使用双层粗边框。

### 4.2 INDEX 首页

- 保持接近 `100svh` 的封面结构。
- 左侧保留 `AI / PRODUCT / MGR.`、定位文案与精简自我介绍。
- 右侧展示已确认的人物主视觉。
- 不重复放置 WORK、EXPERIENCE 等顶部已有入口按钮。
- 手机端保证人脸进入安全区域，标题、人物和 AI 助手互不遮挡。

### 4.3 WORK 工作

- 页头明确表达“AI 不止能生成，还要进入真实工作流”。
- 项目按照时间从近到远排列。
- 每一行依次展示：序号、公司 / 时间、项目与场景、个人角色、关键成果或证据、详情箭头。
- 公司信息与项目信息保持在同一条目，不再分成独立经历区。
- 华为、顺丰丰链、明源云使用同一套信息结构，避免某一项目因边框或卡片结构显得过重。
- Hover 只做背景轻微提亮、左侧信号线出现和箭头位移，不同时叠加缩放、强阴影和多色光效。

### 4.4 WORDS 内容

- 首层即明确显示 `ARTICLE`、`VIDEO`、`VIBE CODING` 类型。
- 桌面采用目录行或三列入口；进入某一类型后显示对应内容列表。
- 类型标签的视觉优先级高于摘要，标题高于标签。
- 暂无真实链接的条目不伪装成可点击内容。

### 4.5 NOW 现在

- 保留日期、城市、类型、标题和摘要。
- 每页最多五条，分页区域保持固定位置，内容数量变化时页面主体高度不跳动。
- 使用时间目录结构，不加入装饰性卡片墙。

### 4.6 CONTACT 联系

- 左侧使用小比例人物形象和精简自我介绍，与首页形成呼应。
- 右侧使用联系方式卡片，电话、邮箱、微信统一对齐，并保留一键复制。
- 微信二维码、简历下载和平台按钮作为独立操作区。
- OPEN TO WORK 仍是全局快捷入口，CONTACT 是完整信息页，两者职责不重复。

## 5. 深色模式

### 5.1 主题策略

- 首次访问跟随系统 `prefers-color-scheme`。
- 顶部提供手动主题切换按钮。
- 用户手动选择后写入 `localStorage`，之后优先使用用户选择。
- 页面切换不重置主题，刷新后保持选择。
- 使用 `data-theme="light|dark"` 与语义化 CSS 变量控制主题，避免每个组件分别判断深色状态。

### 5.2 颜色变量

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| 页面背景 | `#F3F0E9` | `#0B0D0F` |
| 高层表面 | `#FAF8F3` | `#121519` |
| 主文字 | `#111417` | `#F3F0E9` |
| 次级文字 | `rgba(17,20,23,.62)` | `rgba(243,240,233,.64)` |
| 弱分隔线 | `rgba(17,20,23,.12)` | `rgba(243,240,233,.12)` |
| 强分隔线 | `rgba(17,20,23,.24)` | `rgba(243,240,233,.24)` |
| 信号色 | 现有红色 | 现有红色 |

### 5.3 深色视觉规则

- 不使用纯黑大面积铺底，使用近黑和深灰表面建立层次。
- 红色只用于编号、选中状态、关键成果和主要操作。
- 人物皮肤、项目截图和二维码保持真实颜色，不统一灰度化。
- 图片可通过半透明遮罩降低背景亮度，但不得影响人物五官和核心证据可读性。
- 导航、AI 助手、OPEN TO WORK、联系弹窗在深色模式下使用明确的实体背景和浅色描边。
- 半透明效果只用于导航外壳和非关键浮层；正文卡片保持足够对比度。
- 阴影在深色模式中弱化，更多依靠表面明度差和细描边区分层级。

## 6. 组件与状态边界

### 6.1 新增或调整的职责

- `App`：读取当前哈希地址，选择一级页面，并承载全局导航、主题和 AI 助手。
- `TopNav`：只处理菜单选择、移动菜单、主题切换和 OPEN TO WORK，不再监听滚动位置。
- `PageTransition`：统一处理页面进入 / 退出动效与降低动态效果偏好。
- `ThemeProvider` / `useTheme`：处理系统主题、用户选择和本地保存。
- `Hero`、`ProjectGrid`、`ContentFeed`、`NowSection`、`Contact`：分别成为独立页面主体，移除依赖相邻板块位置的样式。

### 6.2 数据流

1. 应用启动时读取 `location.hash`，无有效值时回到 `#index`。
2. 主题状态先读取用户保存值，没有保存值时读取系统偏好。
3. 菜单点击更新哈希；应用根据哈希渲染对应页面。
4. 哈希变化、浏览器前进和后退都经过同一套页面解析逻辑。
5. 内容数据继续由 `src/data/portfolio.ts` 提供，本轮不引入 CMS。

## 7. 异常与降级

- 未识别的哈希地址回退到首页，并将地址修正为 `#index`。
- 本地存储不可用时仍可切换主题，只是不跨刷新保存。
- 浏览器不支持 `matchMedia` 时默认使用浅色模式。
- 动画 API 不可用或用户要求降低动态时，页面立即显示。
- 项目、文章或平台链接缺失时显示静态信息，不生成空链接。

## 8. 响应式规则

- 桌面端导航保持横向菜单；移动端使用纵向菜单面板。
- 移动端不显示音乐控制。
- 移动菜单保留弱分隔线和较大垂直间距，深色模式下完整反白。
- 项目目录在移动端改为“序号 + 主信息 + 结果证据”的纵向组合，避免横向压缩。
- 一级页面页头在移动端缩短高度，不强行占满一屏。
- 所有页面在 390×844、768px、1440px 和超宽桌面下无横向溢出。

## 9. 验收标准

### 导航

- 点击五个一级菜单时直接切换页面，不经过中间页面，也不出现菜单状态跳动。
- 刷新、前进、后退后菜单和页面保持一致。
- 手机菜单能够打开、切换页面并自动关闭。

### 排版

- 五个一级页面拥有一致的页头、留白和信息层级。
- WORK 中公司、项目、角色和成果在同一条目中清晰可读。
- WORDS 首屏能够立即区分文章、视频和 Vibe Coding。
- NOW 每页最多五条且分页时主体高度稳定。

### 深色模式

- 系统主题、手动切换和本地记忆均正常工作。
- 所有正文、按钮、描边、弹窗和二维码在两种主题下可读。
- 切换主题时页面不闪白，人物和图片不失真。
- 不出现网格背景。

### 验证方式

- 为哈希路由、无效地址回退、前进 / 后退、主题优先级和主题保存编写自动化测试。
- 为顶部导航、移动菜单、AI 助手和 OPEN TO WORK 增加浅色 / 深色状态测试。
- 完整执行单元测试和生产构建。
- 在桌面、390×844 手机视口和降低动态效果模式下进行视觉检查。

## 10. 实施顺序

1. 建立哈希页面切换和全局导航框架。
2. 将现有五个板块迁移为独立页面并完成排版统一。
3. 建立主题变量、主题状态和切换按钮。
4. 逐页补齐深色模式和浮层状态。
5. 完成响应式、降低动态效果、测试与构建验证。
